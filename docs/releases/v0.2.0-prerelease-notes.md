## Verification

From a clean checkout of the exact source commit, with no network required:

```text
python3 tools/verify_run_passport.py examples/verified/run-passport.json
python3 tools/verify_run_passport.py examples/verified/run-passport.tampered.json
python3 tools/check_demonstration.py
python3 tools/check_conformance.py
python3 tools/test_public_record.py
python3 tools/test_brand_identity.py
python3 tools/test_release_manifest.py
```

The first verifier command ends with `RUN_PASSPORT_VERDICT: PASS` and exits `0`. The second ends with `RUN_PASSPORT_VERDICT: BLOCK block_owner_authorization_signature_invalid` and exits `1`. The complete suites re-prove both published runs, all PASS/BLOCK demonstrations, the Python/Go agreement and the Brand Identity packet.

## Release manifest, assets and checksums

Set `SOURCE_SHA` to the exact release source and `OUTPUT_DIRECTORY` to a fresh directory outside the checkout, then run:

```text
python3 tools/build_release_manifest.py --worktree . --commit "$SOURCE_SHA" --output "$OUTPUT_DIRECTORY"
```

Run it again with a second fresh external output directory and require `release-manifest.json` and `SHA256SUMS` to be byte-identical between the two directories. Independently hash every manifest path from the exact source tree and compare it with both emitted files before attaching any release asset. The inventory covers the published verifier, both passports and tampered twins, the conformance manifest, all 46 file-backed members of the 48-vector corpus and the tracked marker that reconstructs the directory case; the remaining non-file vector deliberately exercises an absent path.

`SHA256SUMS` is not a signature. It is a checksum inventory of the listed files and nothing more. The Owner's release-signing identity is registered with public fingerprint `SHA256:5EAseYajdN8AATd6zX3f2EUUnfhrNn1XPpLWyHeohHE`, evidenced in [Issue #71](https://github.com/deedseal/deedseal/issues/71); signing the checksum file with that identity and publishing any detached signature remain separate Owner actions that have not been performed. No unsigned checksum file should be described as signed provenance.
